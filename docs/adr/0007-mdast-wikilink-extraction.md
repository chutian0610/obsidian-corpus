# wikilink 提取基于 mdast 文本节点扫描

wikilink 提取最初是"frontmatter 剥离后对正文裸跑正则"，三处硬伤：代码围栏/行内代码里的 `[[x]]` 字面量被当链接（apply 误拒、lint 误报）；`![[附件]]` 嵌入被要求解析到 wiki 页面（带图旧笔记重灌必炸）；解析大小写敏感与 Obsidian 文件名解析不一致。决定引入 `unified` + `remark-parse`，提取改为 **AST 文本节点扫描**——code/inlineCode/html 节点的内容天然不被扫到，`!` 前缀天然保留供嵌入识别，一处实现供 apply/lint/ingest_prepare 三处共用；文本节点内仍用小正则剥 Obsidian `%%注释%%` 与 `$数学$`。备选是零依赖的手写遮蔽层（先剥代码块再跑正则），但嵌套围栏、缩进代码、波浪线围栏等长尾坑多——竞品自研扫描器的 changelog 里堆着这类修复，不重蹈。代价是两个纯函数式依赖（与 zod/yaml 同量级），个人库规模下每页解析的性能开销可忽略。嵌入语义随之定稿：**嵌入不参与目标存在性校验**（附件不是页面），但解析到页面的嵌入计入该页入链；目标解析改大小写不敏感；锚点维持只剥不校验。
