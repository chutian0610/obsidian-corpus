# 受管约定文本的版本化与自动升级

corpus 根 `AGENTS.md` 是 schema 层的约定文本，随工具演进（Ingest 第 0 步、git 边界前置、编译价值门槛等）——但既有 corpus 里的 agent 每个会话都读它行事，文本停在初始化那天就意味着行为回退。决定把约定文本做成**受管文本**：首行带版本标记 `<!-- corpus-agents: vN -->`，每个已发行版本整篇留底在注册表（agentsFile.ts 的 SHIPPED_AGENTS_MD）；init 重跑时，仅当既有文件**与某个已发行版本一致（除尾部换行，编辑器常自动补末尾换行；其余逐字节）**且版本落后时才自动升级并随 init 单 commit 入库；内容对不上任何已发行版本（改过、或更早未留底）则一律不动，在结果 customized 中提示手动合并。备选方案是把约定拆成"机器管理 + 人类附注"两份文件（升级永远安全），代价是 corpus 根多一个文件、且存量库要迁移；逐字节比对方案对已有库零迁移成本，且绝不会覆盖人类修改——升级失败的最坏结果只是"提示手动合并"。
